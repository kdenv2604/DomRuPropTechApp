# Подключение служебного портала

Здесь записано то, что проверено 4 октября 2026 года по веб-клиенту и настоящей
разрешённой служебной сессии. Секретные значения в этот документ не попадали.

## Авторизация

Портал расположен по адресу `https://lk.proptech.ru`, а вход выполняет Keycloak:

- issuer: `https://id.dom.ru/realms/lk`;
- client id: `lk-frontend`;
- страница входа: `/protocol/openid-connect/auth`;
- выдача и обновление токена: `/protocol/openid-connect/token`;
- выход: `/protocol/openid-connect/logout`;
- веб-клиент использует Authorization Code и PKCE `S256`;
- запросы портала передают `Authorization: Bearer <токен>`;
- форма действительно принимает буквенно-цифровые `username` и `password`.

Прямой вход с `grant_type=password` и обновление через `refresh_token` проверены
на служебной учётной записи. Пароль приложение не сохраняет. Токены каждого
логина шифруются отдельной записью при помощи Android Keystore.

Веб-сборка сообщает три основы для запросов:

- `https://lk.proptech.ru/api` — API самого кабинета;
- `https://public.proptech.ru` — объекты, дома, устройства и камеры;
- `https://bff.lk.proptech.ru` — отдельный сервер кабинета.

Из открытого кода веб-клиента подтверждены следующие запросы:

| Назначение | Запрос |
|---|---|
| Профиль и доступы | `GET https://public.proptech.ru/accounts/v1/accounts/me` |
| Дома компании | `GET https://public.proptech.ru/houses/v1/companies/{companyId}/houses` |
| Подъезды компании | `GET https://public.proptech.ru/houses/v1/companies/{companyId}/porches` |
| Домофоны | `GET https://public.proptech.ru/devices/v2/devices/intercom?companyId={companyId}` |
| Открыть устройство | `POST https://public.proptech.ru/devices/v2/devices/{deviceId}/open` |
| Данные камеры | `GET https://public.proptech.ru/devices/v2/devices/{deviceId}/camera` |
| Живое видео | `GET https://public.proptech.ru/devices/v2/devices/{deviceId}/camera/video` |
| Кадр предпросмотра | `GET https://public.proptech.ru/devices/v2/devices/{deviceId}/camera/preview` |
| Код устройства | `GET/POST https://bff.lk.proptech.ru/v1/web/codes/{accessControlId}` |
| Доступные для кодов устройства | `GET https://bff.lk.proptech.ru/v1/web/codes/available-devices` |

В теле открытия приложение, как список объектов веб-клиента, передаёт
`{"source":"objects"}`. Успех принимается только при положительном поле `status`.
Автоматическая проверка не отправляла этот POST, чтобы не открыть настоящую дверь.

Раздел кодов кабинета умеет назначать пятизначный код, в веб-интерфейсе встречается
период `P7D`. Наше приложение выполняет только безопасный GET уже назначенного
кода. Оно не выдаёт этот служебный код за гарантированно одноразовый.

## Что подтверждено настоящей сессией

1. Вход и сохранение отдельной сессии работают.
2. Профиль содержит спецификацию и компанию.
3. Дома, подъезды и домофоны связаны полями `route` и `parentRoute`.
4. Один проверенный дом отдал восемь подъездов и восемь домофонов.
5. Запрос действующего кода вернул успешный ответ.
6. Видеометод вернул HTTPS-поток с типом `video/x-flv` и кадр предпросмотра.
7. Поток успешно воспроизведён нативным Android-плеером на настоящем смартфоне.

Ответ дома содержит строку `address` и `location.fiasId`. Отдельного читаемого
поля с названием города в проверенной структуре дома нет. Поэтому приложение
сначала выделяет город или посёлок из полной строки `address`, затем использует
`locationName` из профиля компании, а при его отсутствии читает штатную карточку
`GET /companies/v1/companies/{companyId}`. «Населённый пункт не указан» остаётся
только последним честным вариантом, если портал не отдал название ни одним из
этих способов.

Отдельной ручной проверки ещё требуют фактическое открытие двери и отзыв сессии
сервером при выходе.

Секреты, cookies, токены и настоящие пароли в логи и репозиторий не записываются.

## Граница реализации

Настоящий вход, каталог объектов и команды собраны в `ProptechDomruRepository`.
Остальные части приложения не знают URL, токены или формат JSON. Для каждого
аккаунта хранится свой набор токенов, а одинаковые адреса объединяются только на
уровне экрана.

Перед построением общего списка приложение проверяет профиль каждого аккаунта.
Сломанная сессия исключается из запросов, поэтому она не мешает дверям остальных
логинов. Новый пароль разрешено вводить только после ответа `401`, ошибки
обновления сессии или отсутствия refresh token. Только это состояние открывает
смену пароля и удаление учётки; сетевой сбой и `403` не разрешают ни одно из этих
действий.

## Правила повторов

- Безопасное чтение списка, кода или ссылки камеры: максимум три попытки с
  короткой паузой.
- Загрузка самого видеопотока: первая попытка и не больше двух повторов, затем
  показывается ручная кнопка.
- Вход: одна попытка на одно нажатие человека.
- Обновление истёкшей сессии: одна попытка, затем нужен новый вход.
- Открытие двери: одна попытка. При потере ответа показываем неопределённый
  результат и просим человека сначала проверить дверь.

POST открытия нельзя автоматически отправлять второй раз: первая команда могла
дойти до сервера, даже если ответ потерялся.
