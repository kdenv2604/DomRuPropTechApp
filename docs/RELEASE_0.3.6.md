# Дом.ру — тех. аккаунт 0.3.6

Камера в карточке подъезда теперь сама получает свежую ссылку после обрыва,
завершения потока и долгого ожидания кадров. Даже при прежнем URL запускается
новое соединение. Кнопка «Повтор» удалена; камера остаётся только встроенным
предпросмотром. Полноэкранного просмотра и звонков в сервисном приложении нет.

Возврат из фона, смена сети и отмена добавления аккаунта восстанавливают открытую
камеру. Закрытие карточки и фон освобождают плеер и отменяют повторы. При нескольких
аккаунтах используются только разрешённые источники той же физической двери;
временный сбой одного аккаунта или компании не скрывает остальные. Неполный каталог
не сохраняется в кэш. HTTP/HTTPS-переадресации медиасервера поддерживаются;
формат определяется по MIME и адресу, а не по названию видеокодека.

Внизу настроек показаны **Версия 0.3.6 · Сборка 10**. Эти значения берутся из
BuildConfig и обновляются при сборке приложения. Прежние оформление и дерево
«город → улица и дом → подъезд» сохранены.

Проверки: 52 JVM-теста, 0 failures/errors; Android lint — 0 ошибок,
39 предупреждений. Три теста реального Media3-декодера на Android 14 прошли
за 13,835 с: обрыв и конец потока с новым кадром по тому же URL, поздний первый кадр
после watchdog, отмена восстановления и освобождение ресурсов при скрытии/фоне,
возобновление после возврата. Использован локальный синтетический H264-видеофайл;
реальные двери эти тесты не открывали. Проверены демо-карточка с прежними кнопками
и восстановление после отмены формы добавления аккаунта. Длительный просмотр
на настоящей камере после обновления ещё требует полевой проверки.

Служебный API авторизации и команды двери сохраняются. Неподтверждённый абонентский
метод продления видеосессии в сервисный клиент не переносился: используется
штатный служебный `GET camera/video` с `x-specification-id`.

APK использует прежний постоянный ключ подписи. Ставить обновлением поверх 0.3.5,
не удаляя приложение: существующие аккаунты и настройки сохраняются.
